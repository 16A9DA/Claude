# Queries — E-Commerce Data Utilities

A TypeScript project providing typed query functions over a SQLite database modelling a simple e-commerce system. Built as a learning exercise for [Claude Code hooks](https://docs.anthropic.com/en/docs/claude-code/hooks).

## What It Does

- Initialises a local SQLite database (`ecommerce.db`) with a full e-commerce schema: products, categories, inventory, orders, customers, reviews, promotions, and shipping.
- Exposes a library of typed async query functions in `src/queries/`, each accepting a `Database` instance and returning a Promise.
- Runs three Claude Code hooks automatically on every file save to enforce code quality (see [Hooks](#hooks) below).

```
  tsc.js                # PostToolUse — type-checks after every TS edit
  read_hook.js          # PostToolUse — additional read-time hook
scripts/
  init-claude.js        # Writes .claude/settings.local.json from template
sdk.ts                  # Example usage with the Anthropic Claude Agent SDK
```

## Getting Started

```bash
# Install dependencies and configure Claude Code hooks
npm run setup

# Initialise the database and schema
npx tsx src/main.ts

# Run the SDK example
npm run sdk
```

> **Note:** There is no test runner configured — `npm test` exits with an error.

## Hooks

This project is designed to teach how Claude Code hooks work. Three hooks are wired up via `.claude/settings.local.json` (generated by `npm run setup`):

| Trigger                    | File                  | What It Does                                                                                                                                                        |
| -------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PreToolUse` (Write/Edit)  | `hooks/query_hook.js` | Uses an AI agent to scan `src/queries/` and block the change if a new function duplicates existing query logic. Exits `2` with feedback if duplication is detected. |
| `PostToolUse` (Write/Edit) | prettier              | Auto-formats the saved file with Prettier.                                                                                                                          |
| `PostToolUse` (Write/Edit) | `hooks/tsc.js`        | Runs a full TypeScript type-check via `tsconfig.json`. Exits `2` with diagnostics if there are type errors.                                                         |

Hook activity is logged to `pre-log.json` and `post-log.json` in the project root.

### How the Duplicate-Query Hook Works

`query_hook.js` reads the incoming tool call from stdin (Claude Code passes a JSON payload), resolves the file path, and — if the target file is inside `src/queries/` — asks a Claude agent to compare the proposed change against every existing query file. If the agent finds that the new function duplicates existing functionality it prints the reason to stderr and exits with code `2`, which causes Claude Code to block the write and surface the feedback to the user.

### How the Type-Check Hook Works

`tsc.js` uses the TypeScript compiler API directly (no `tsc` subprocess). After every `.ts`/`.tsx` file write it parses `tsconfig.json`, creates an in-memory program, and collects pre-emit diagnostics. Any errors are printed to stderr and the hook exits `2`, blocking the write until the errors are fixed.

## Database Schema Highlights

- `categories` is self-referential (`parent_category_id`).
- `inventory` has a composite unique key `(product_id, warehouse_id)` — stock is tracked per warehouse.
- `reviews` has a composite unique key `(product_id, customer_id, order_id)` — one review per purchase.
- `promotions.discount_type` is one of `'percentage'`, `'fixed'`, `'free_shipping'`.
- `orders.status` lifecycle: `pending → processing → shipped → delivered` (or `cancelled`/`refunded`).

## Writing a Query

All query functions live in `src/queries/` and follow this pattern:

```typescript
import { Database } from "sqlite";

export async function getProductBySku(db: Database, sku: string): Promise<any> {
  return db.get(`SELECT * FROM products WHERE sku = ?`, [sku]);
}
```

- Use `db.get()` for single-row lookups.
- Use `db.all()` for multi-row results.
- The `sqlite` wrapper returns Promises — use `async/await`, not callbacks.
